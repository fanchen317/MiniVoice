# 共享界面复刻标准

手机参考当前 Android 正式主界面；电脑参考当前 Mac 页面。各自保持原有布局关系、按钮图标、材质、主要操作和导航行为。共用核心与业务协议，界面按设备类型分开；手机横屏仍使用手机交互规范。不同系统字体、键盘、系统状态栏和授权页面允许遵循平台标准；不能据此宣称逐像素完全相同。

## 尚未达到完全复刻的部分

- 文件夹授权、扫描和诊断常用入口已进入手机共享设置；完整缓存管理、音乐库检查等仍打开原设置页。
- 批量选择与集合操作、歌单管理、歌曲信息及歌词详情已迁移；元数据写入编辑和部分深层歌曲操作尚待迁移。
- 音乐墙的原生液态玻璃折射和全部缩放过渡仍需真机逐项比对，现阶段是共享材质实现，不保证与每个 GPU 逐像素相同。
- iOS 已接共享核心，尚未接共享 WebView 宿主；其他平台也需要各自实现音频与目录权限适配。

因此入口继续保持“跨平台界面试用”，未替换默认主界面。后续按此清单收敛到完整复刻，不能通过删去原功能来宣布完成。

## 本轮验证

`Scripts/test-android-ui.sh` 的 portable 阶段覆盖真实 WAV 播放、真实本地封面解码、收藏落盘、队列、五种模式映射、三种样式 × 深浅模式截图、隐藏/重开列表锚点、歌手网格进入返回与重开恢复、音乐墙缩放/聚焦。截图中音乐库为合成测试数据，不使用用户音乐。

`node --test Shared/UI/test/*.test.mjs` 验证导航规则、长整数 ID、收藏/最近/歌单过滤、墙可见区域、串行状态写入与宿主桥接。桌面 Swift 和 Vite 构建、现有桌面测试单独验证。

## 设备类型基准（2026-10-22 更新）

- **电脑端**以现有 Mac 页面为准，包括窄窗口；Electron 的桌面预览直接复用 Mac App 组件，不加载手机 PortablePlayer/CSS。Windows/Linux 后续沿用电脑基准。
- **手机端**以现有手机页面为准，Android、iOS、鸿蒙使用触控/抽屉/底部卡片的交互规范；横屏或平板的宽度变化不改变设备类型。当前已接入 Android，iOS/鸿蒙宿主尚未接入。
- 两端共享核心与数据协议、可共享的逻辑；布局、导航和输入交互按设备类型分开，不以同一套手机 UI 强行覆盖电脑。

本轮手机端新增：歌曲长按菜单、批量选择/收藏/加入与移出歌单，歌单重命名/删除，名称变更时迁移查询/锚点/展开状态，歌曲信息与解析后的歌词详情。设置中已接入授权目录列表、系统选择目录、递归扫描、重新扫描、清空最近播放、诊断导出入口。缓存管理、音乐库检查及更深的设置仍保留原设置入口；元数据写入编辑仍待迁移。

共享设置里的重新扫描只出现在设置内。歌单删除、移除歌曲只更改集合引用；音乐文件保留。批量写入先验证全部歌曲与目标歌单，未知 ID 会整批拒绝。

## 音乐墙几何与墙内聚焦修正

共享手机界面去掉固定尺寸网格，使用原桌面/Android 一致的加权递归拼墙和周期重复实例。几何函数移入共享模块，桌面重导出同一实现，桌面页面不变。聚焦卡片在墙内占据方形空间，邻近封面按公共边界让位；相机用 520ms 过渡居中，手势可中断。播放内容以屏幕像素排版，墙缩放不会同步缩小歌词字号；歌词展开使用墙视口。歌词居中改为计算滚动容器与当前行之间的相对位置，避免嵌套卡片坐标造成裁切。

本轮并未完成原音乐墙所有交互：缩放期间的紧凑卡片分级，以及完整液态折射仍需继续对齐。拖动已加入 420ms 惯性衰减，单击仅聚焦、双击或播放按钮播放，缩放范围与原手机端一致为 60%～120%。新增几何测试与实际 WebView 中的加权尺寸、墙内聚焦、歌词可见范围检查。
