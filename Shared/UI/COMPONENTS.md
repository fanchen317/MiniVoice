# MiniVoice 自有组件标准

## 当前重写范围

当前只重写 macOS 和 Android。以各自现有页面设计与操控逻辑为验收基准，使用 MiniVoice 自有组件重建应用界面，并共用业务规则。先完成两端的功能、交互与稳定性验收，再考虑 iOS、Windows；鸿蒙、Linux 同样不属于本轮实施范围。保留已有其他平台代码，不继续扩展其适配，也不将抽象接口视作平台实现。

## 产品边界

移动端包含手机和平板，以现有 Android 页面设计和操控逻辑为参照，主输入为触控；桌面端包含电脑，以现有 Mac 页面设计和操控逻辑为参照，主输入为键鼠。primaryInput 记录产品主输入，桌面 input 继续记录当前鼠标/键盘焦点模式，两者不混用。操作系统、窗口宽度、横竖屏不能互相替代：宽平板仍是移动端，窄电脑窗口仍是桌面端。本轮移动端宿主为 Android，桌面宿主为 macOS；其他平台只保留未来扩展可能。

共用的是组件语义、状态规则、数据协议、几何和可复用行为。两端的布局、密度、动画和输入反馈保留各自基准。系统负责音频、授权选择器、通知和媒体会话等平台能力；应用内容控件由 MiniVoice 渲染。使用 WebView/DOM 的语义元素不等于使用 Android View 或 AppKit 内容控件；运行容器和系统服务仍需宿主。

## 已接入的第一组组件

| 组件 | 共用标准 | 移动端呈现 | 桌面端呈现 |
| --- | --- | --- | --- |
| ActionButton | 名称、禁用、忙碌、选中状态；默认不提交表单 | 最小 44 CSS px 触控区域，沿用 Android 皮肤 | 保留 Mac 按钮皮肤、悬停和快捷键上下文 |
| DialogBoundary | 最顶层拥有键盘；Tab 包含所有可用交互元素；焦点不得逃逸；关闭后恢复焦点且不滚动 | 默认聚焦面板，手机底部弹出，平板居中 | 默认聚焦首个输入字段，沿用 Mac 浮层与运动效果 |
| Presentation | 宿主选择产品家族；尺寸只决定家族内部布局 | phone/tablet、横竖屏、compact/wide | computer、横竖窗口、compact/wide |
| Slider | 自绘轨道与滑块；拖动预览、释放提交、取消不提交、键盘端点；轮询不覆盖手势 | Android 进度与触控尺寸 | Mac 进度、音量和音乐墙显示比例，保留桌面皮肤 |
| Scrollbar | 自绘滑块、拖拽映射、自动隐藏、取消捕获和键盘滚动；不使用系统滚动条 | 触控尺寸与强调色，停止滚动后淡出 | Mac 色彩、鼠标悬停和键盘控制 |
| Checkbox skin | 自绘勾选外观，保留语义和键盘访问 | 深浅模式色值，统一描边 | 暂保留现有 Mac 实现 |

主要文件位于 `src/components/`。移动端的 Button、两端 Modal、桌面 IconButton 已接入这些共用基础；不是说全部旧按钮、旧页面已经完成迁移。

## 实现约束

1. 业务组件通过宿主适配器调用能力，不依赖 Java/Swift 类型。
2. 深浅色和材质由应用的视觉变量决定，不随系统原生控件默认主题漂移。
3. 图标视觉尺寸可以小于触控区域；不得以缩小可点区域解决布局问题。
4. 导航、排序、搜索、滚动锚点、展开和墙相机属于页面状态，弹窗焦点恢复不能改变页面位置。
5. Escape/系统返回逐层关闭；桌面播放快捷键不能穿透弹窗。Tab 必须覆盖按钮、输入框、复选框和操作链接；普通按键必须能到达自绘滑块等内容控件。
6. 平板布局通过可用空间调整，保持触控操作和移动端导航规则。键鼠支持可作为辅助能力，不能将平板自动换成桌面家族。
7. 新组件需验证真实交互与状态，不通过删除原功能缩小复刻范围。

## 后续迁移范围

侧边栏、上下文菜单、列表/网格、拖拽滚动条、播放栏、歌词和音乐墙仍需逐项收敛到组件边界；音乐墙的缩放分级和液态材质也尚未完整对齐。原 Android 默认播放器仍保留，跨平台界面仍处于试用阶段。iOS/鸿蒙共享界面宿主尚未接入。
