# MiniVoice 安卓版

这是独立的 Android 本地播放器工程，复用 MiniVoice 的产品名称与播放模式。首页提供基于本机歌曲封面的音乐墙、可开合的深色侧栏及底部播放条；左下角设置按钮打开音乐库设置。当前包含用户明确授权的指定文件夹扫描、子文件夹开关、重新扫描、歌曲数量、缓存清理、搜索、歌手与专辑浏览、后台播放及系统媒体控制、五种播放模式、收藏、最近播放、歌单和 LRC 文件导入。收藏、歌单及导入的歌词保存在应用本地数据中；音乐文件不会复制或修改。

执行 `Scripts/build-android.sh` 可直接生成 `.build/Android/MiniVoice-debug.apk`。也可在 Android Studio 打开 `Android/`，安装 Android SDK 35 和 Build Tools 35.0.0 后运行 `:app:assembleDebug`。支持 Android 10 及以上。

脚本会依次查找 `ANDROID_HOME`、`ANDROID_SDK_ROOT`、`Android/local.properties` 的 `sdk.dir`，然后查找 Android Studio 常用 SDK 目录、Homebrew 路径和项目的 `.build/android-sdk`。优先使用 Build Tools 35.0.0，也支持更新的稳定版本。显式配置的 SDK 不完整时会给出缺少组件的提示，不会删除已有 APK。自定义路径可这样运行：

```bash
ANDROID_HOME="/你的/Android/sdk" ./Scripts/build-android.sh
```


音乐墙使用与 Mac 版相同的加权封面分割算法，并支持双向拖动、双指缩放、点按卡片聚焦、双击播放和封面缓存；移动端控制方式按触屏适配。尚未迁移标签编辑、在线歌词和离线 AI 歌词匹配。安卓通过系统文件夹选择器授权读取用户添加的音乐目录，不直接读取 Mac 的音乐目录；需将音频文件传到手机。安卓应用缓存位于系统分配的应用专属外部存储目录，设置中显示真实路径并可查看和清理；文件管理器能否访问 Android/data 由系统限制决定。

播放服务向 Android 系统媒体会话提供歌名、歌手、专辑、时长和内嵌封面，并同步播放、暂停、上一首、下一首及进度拖动。锁屏和通知栏中的播放器外观由手机系统决定；应用提供的是数据与控制接口。首页壁纸绘制到透明状态栏后方，按钮按状态栏安全区域下移。

点击系统锁屏或通知栏的媒体卡片会返回音乐墙并定位当前歌曲。触屏按钮使用安卓按下波纹反馈，音乐墙卡片保留按下缩放、聚焦和相邻卡片回流动画；鼠标悬停样式不迁移到触屏。

扫描歌词优先读取音频内嵌标签：MP3 的 ID3 USLT/SYLT、FLAC 的 Vorbis LYRICS/UNSYNCEDLYRICS，以及 M4A 的 ©lyr。没有有效内嵌歌词时，使用设置里所选音乐目录的 `lrc/` 文件夹，并严格按原始音频文件名去掉扩展名匹配，例如 `Music/843 - 前田爱 - I wish.flac` 对应 `Music/lrc/843 - 前田爱 - I wish.lrc`；不使用歌曲标题或去编号猜测匹配。子目录的 `lrc/` 同样适用。支持 UTF-8、UTF-16 和 GB18030。手动导入只在没有有效内嵌歌词时优先于外部 LRC。系统媒体库权限不包含旁边的歌词文本，需要选择音乐目录。

音乐墙的聚焦卡片会按当前播放进度显示同步歌词及相邻歌词行。卡片上的播放按钮在当前歌曲播放时切换暂停和继续，播放其他歌曲时切换曲目；底部播放条仍可拖动进度。

播放队列与音乐墙工具从底部打开半屏面板。音乐墙工具显示 60%–120% 的缩放比例；底部播放条使用加粗的进度轨道和完整滑块。点按播放条里的歌曲名称定位正在播放的封面，长按名称打开歌词；侧边栏使用较窄的滑入面板，搜索框从右上角按钮原位向左展开。

底部播放条的上一首、下一首和播放队列图标按安卓触屏尺寸直接绘制，图形和触控区域均比桌面图标适配版本更大。

扫描分为查找文件和读取标签两个阶段：设置中先显示已发现的歌曲数量，再显示已处理/总数、百分比及当前文件名。修改子文件夹开关会重新扫描；扫描期间修改文件夹会在当前扫描结束后自动补扫。扫描异常会恢复可重试状态并保留现有音乐库。

歌曲优先使用音频标签，增加 ID3v2.2/v2.3/v2.4（含 UTF-16 中文标签）的直接读取，避免部分安卓设备将文件名当作歌曲标题。标签缺失时，`026 - 许嵩 - 安琪.mp3` 会回退为歌名“安琪”、歌手“许嵩”。封面依次尝试系统内嵌图片、直接解析 ID3 图片、同目录同名图片或 `cover/folder/front/album` 图片，以及系统专辑封面；音乐墙和系统播放器使用相同的封面读取逻辑。歌词支持 `lrc/` 目录中的同名文件、增强 LRC 的 `<分:秒.毫秒>` 逐字标记及 `[offset:]`；逐字标记用于还原干净的行文字，当前仍按行同步显示。

执行 `Scripts/test-android.sh` 运行 JVM 解析回归测试；需要 Android SDK 35，可通过 `ANDROID_HOME` 指定 SDK。可额外传入测试样本“026 - 许嵩 - 安琪.mp3”的路径，验证真实文件的 UTF-16 标签及内嵌图片读取。

聚焦卡片沿用 Mac 的上下布局：全宽连续遮罩，顶部歌曲信息，播放状态胶囊，中部自动换行的同步歌词，底部上一首、播放/暂停、下一首、收藏、展开/收起、时间与白色细进度条。预览未播放歌曲时只显示信息和播放按钮；点击卡片空白处不会切换播放。窄屏时间独立成行，控制按钮保留 44 dp 触控区域；进度条支持点按和拖动，拖动时不会移动音乐墙。展开后隐藏浮动工具和底部播放条，返回键或收起按钮恢复。


## 两台 Mac 共用开发签名

项目包含固定开发密钥 `Android/signing/debug.keystore` 及公开证书指纹 `Android/signing-certificate.sha256`，两者均纳入 Git。两台 Mac 拉取相同提交后直接使用原打包脚本或 Android Studio 即可，默认别名 `androiddebugkey`、密码 `android`。无需各自生成或手动复制密钥。此密钥用于开发测试；正式对外发行应使用独立保密的发行密钥。

脚本与 Gradle 都验证固定证书指纹；缺失或不一致则停止，不会自动生成密钥或回退到本机 `~/.android/debug.keystore`。请不要在两台 Mac 设置不同的 `MINIVOICE_KEYSTORE` 等签名环境变量；默认使用仓库内开发密钥。

当前统一证书 SHA-256：

```text
d014c3673246e0a038e1e0c36fc1a8990f4fa313c713160a13eda5d10bd01223
```

### 已安装旧版的兼容

统一仓库签名能避免后续两台 Mac 再次产生不同签名，但当前手机上的旧版必须与上述证书相同才能直接覆盖。先在旧 Mac 使用 Android SDK 的 `apksigner verify --print-certs /旧版.apk` 比较 `Signer #1 certificate SHA-256 digest`。**暂时不要卸载手机应用。**

若旧版证书不同，应以旧 Mac 实际打包所用的原始私钥作为统一开发密钥。检查旧项目的 `Android/signing/debug.keystore`、`.build/Android/debug.keystore` 或 `~/.android/debug.keystore`。确认原始私钥后，手动移走项目的 `Android/signing-certificate.sha256`（这是一次有意更换统一身份的操作），再执行：

```bash
bash Scripts/import-android-signing.sh /旧Mac原始密钥的绝对路径/debug.keystore
```

将更新后的密钥和证书指纹一起提交、同步到两台 Mac。导入脚本会备份已有本地密钥，备份不会进入 Git。非默认别名/密码需要通过 `MINIVOICE_KEY_ALIAS`、`MINIVOICE_STORE_PASSWORD`、`MINIVOICE_KEY_PASSWORD` 在两台 Mac 同样配置。

只有原始私钥才能签出可覆盖旧版的 APK；旧 APK 无法恢复私钥，修改版本号或指纹也不能绕过系统校验。原私钥彻底丢失时只能重装，卸载会删除应用私有缓存、收藏和歌单。



音乐墙搜索按钮改为右上角原位展开：圆形镜片先略微放大，再向左展开成胶囊搜索框，输入区渐显，图标转为薄荷绿；关闭时沿原位收回。展开完成后才唤起键盘，支持清空、搜索键收起键盘和返回键收起搜索框。

定位当前播放歌曲直接显示完整的正方形播放卡片，不播放镜头平移动画；已聚焦时重复定位不会重新展开。定位保持当前“最近播放”、收藏或歌单等页面，不强制切回音乐库。如果当前列表不含播放歌曲，会临时显示该歌曲而保留当前页面。手动点按其他卡片仍保留聚焦回流动画。

扫描最后会执行“缓存封面”阶段：先保存最长边 640 像素的磁盘缩略图，再给整份歌曲列表准备常驻小预览（像素内存预算约 24 MiB）。音乐墙平移、缩放和定位时直接保留预览，高清缩略图使用共享内存/磁盘缓存，不会因内存缓存淘汰而闪回音符占位图，也不会为此重新从音频文件提取封面。音频或同目录图片的修改时间/大小改变后，重新扫描会刷新对应缓存。系统播放器共用封面缓存。

歌词在扫描阶段完成内嵌读取和同名 LRC 匹配，并持久缓存解析前的原文。读取中的请求会在页面退出时失效，回到页面可继续使用扫描结果；界面区分加载、权限和匹配失败状态。纯文本歌词也可显示。

主音乐墙使用透明的底部导航栏，背景延伸到系统手势指示条下方；底部播放条、音乐墙工具和侧栏按导航栏 inset 留出安全间距。系统的小白条保持可见，由系统管理。侧栏品牌说明显示完整的“音乐让生活更美好”，空间不足或字体放大时换行，标题区高度随文字增长。

缓存保存在应用专属外部持久目录 `Android/data/com.xcosmos.minivoice/files/library/`，同签名覆盖安装、升级和日常打开均复用已有封面与歌词缓存；升级会迁移仍存在的旧封面缓存，不向音乐目录写入文件。手动点击“重新扫描”会先清空派生缓存，再扫描歌词并重建封面；歌曲、原始 LRC、收藏、歌单及手动导入内容保持不变。卸载应用会由系统删除本地数据。

音乐墙的侧栏、搜索、工具按钮统一使用 56 dp 圆形玻璃背景和 24 dp 图标。原生按钮按下缩小、松开回弹，卡片中的 Canvas 控制按钮同样有缩放和高亮反馈。搜索内容为空时，点按搜索区之外会收回圆形按钮且不拦截原操作；已有查询不会被外部点击清除。比例滑块直接使用 60%–120% 的绝对百分比，并与实际缩放同步；初始化/切换列表不再隐式重置比例，“恢复 100%”和“回到起始位置”会明确恢复 100%。

音乐墙比例低于 70% 时，聚焦卡片采用精简显示：播放状态、歌曲名、歌手和展开按钮；歌词、卡片进度条及其他控制均隐藏并取消触控区域。展开播放器后恢复完整控制。状态胶囊的文字、图形和圆角随卡片尺寸等比缩放，未聚焦卡片的歌名字号也已缩小。播放模式统一放在右下角音乐墙设置中，以五个带说明和选中标记的选项直接切换，选择持久保存，不再在卡片中循环切换或弹 Toast。

横竖屏旋转由当前 Activity 处理配置变化，保持音乐库、缓存、当前分类、播放队列和播放进度，不重新触发扫描。横屏进入沉浸模式，系统栏可由边缘滑动临时唤出，三个浮动工具按钮向屏幕外移出；播放条保留竖屏宽高并放在右下角，聚焦卡片在左侧安全区域垂直居中。切回竖屏恢复工具按钮、全宽底部播放条和居中卡片。横屏首次扫描期间显示“正在载入音乐库”，避免误显示需要重新添加文件夹。

展开播放器时，封面与渐变遮罩铺满整个窗口，交互内容单独避让状态栏、刘海和底部导航安全区；全屏状态不再保留卡片外边距和绿色边框。展开/收回采用 420 ms 连续几何过渡，快速反向操作从当前进度继续。底部播放条配合淡出/淡入，收回后恢复原位置；横屏展开时仍保留右下角播放条，播放器内容位于左侧安全区域。

扫描结果保存在应用私有文件 `library-cache/index-v1.json`，包含歌曲、来源、封面引用和已读取的歌词。重开优先恢复索引，同一进程中的界面重建也复用已准备的歌曲对象；没有有效索引、选择的目录或扫描范围改变时才重新扫描。新增或修改音乐、封面、LRC 后请使用“重新扫描”。升级到索引版本后首次启动需要扫描一次。

封面主缓存按歌曲 URI 使用稳定文件名，版本变化覆盖原缓存；成功扫描后删除已移除歌曲和旧版生成的封面缓存。每首有封面的歌曲只保留一张主缓存，无封面的歌曲只保留缺失记录。主图最高 1600 像素、JPEG 95，普通墙图和聚焦清晰图从同一主文件生成内存图片。歌词保留增强 LRC 的逐字时间并连续高亮，逐行 LRC 使用行间时间估算高亮并平滑滚动；估算效果不等同于真实逐字时间。

设置页采用安卓分组列表：外观、音乐文件夹、音乐库、缓存与存储、歌词。播放器样式可在简易、音乐库列表和音乐墙之间即时切换，共用同一个播放服务、音乐库和底部控制条。界面外观支持跟随系统、浅色和深色，设置页与简易／列表页同步更新；音乐墙保留封面上的深色播放控件以保证可读性。设置值保存在应用本地，重开后恢复。简易页点按当前歌词可跳到该句，长按打开歌词详情／导入。

文件夹显示系统授权目录的可读路径，点按目录可移除授权来源；重新扫描复用封面缓存，重建缓存经确认后清理并重新扫描。设置页不会显示 Mac 菜单栏图标、窗口关闭方式或桌面快捷键选项。

音乐墙右下角的页面设置提供与 Mac 相同的排序分类：歌曲、收藏、歌单和歌手／专辑二级歌曲页共享“歌曲名称、歌手姓名、专辑名称、添加时间、更新时间”；歌手和专辑外层分别保存“名称、歌曲数量”的排序，支持正序／降序。最近播放按播放时间排列，不显示普通排序选项。默认歌曲按更新时间降序，分组按名称正序。

歌手与专辑外层单击分组卡片进入二级歌曲墙，顶部返回入口及安卓返回键可回到外层；返回保留外层的平移位置和缩放。外层卡片仅显示分组与歌曲数量，不使用代表歌曲的播放状态。二级页播放队列采用当前显示顺序。系统音乐库的添加时间读取 DATE_ADDED；授权文件夹缺少创建时间时以首次扫描发现时间记录，更新时间使用音频文件修改时间。时间字段随音乐库索引缓存，不要求为新增排序功能重建封面。


目录增删会立即更新可见音乐库、清除失效索引并异步删除已移除目录的封面和歌词缓存，随后重新扫描建立索引；过期扫描不能覆盖新来源的结果。移除最后一个授权目录后保持空库，不自动回退扫描系统音乐库。目录移除也会解除该目录授权，并移除播放队列中的相关歌曲。缓存现已迁移到系统分配的 `Android/data/com.xcosmos.minivoice/files/library/`。禁用云备份和设备迁移恢复，防止新安装恢复旧目录配置；这不会自动清除升级前已经存在的数据。

侧栏恢复为上下避让安全区的悬浮面板。设置页由同色背景覆盖系统栏并采用对应深浅图标，不再提供只读歌词说明分组。普通歌曲定位保留聚焦过渡，切换分类时直接定位当前播放歌曲。动态玻璃在 Android 12 及以上使用 GPU RenderEffect，避免主线程周期截图和软件卷积；Android 10/11 的动态控件使用稳定半透明渐变，侧栏使用打开时的模糊快照。按钮使用弱波纹、缩放和遵循系统触觉设置的反馈，不请求自定义振动强度。


播放队列与音乐墙配置统一使用深色半透明面板，首次打开和拖动后均直接透出底层音乐墙，不再在首次打开时叠加整张模糊截图。侧栏设置入口使用与其他悬浮按钮相同的 56 dp 圆形玻璃轮廓。弹层以固定高度配合位移完成半屏／安全区展开／下拉关闭，避免每次拖动重新布局长队列；开场、回弹和退出共用一个可取消动画，关闭后不再接受新拖拽。列表在顶部向下滑动交给面板，展开后的其余滑动由列表处理。


### 存储目录与升级行为

使用系统 `getExternalFilesDir()` / `getExternalCacheDir()`，默认主存储布局如下（包名保持 `com.xcosmos.minivoice`，不改变大小写）：

```text
Android/data/com.xcosmos.minivoice/
├── files/
│   ├── config/settings.json       设置、收藏、歌单等偏好值的自动 JSON 快照
│   └── library/
│       ├── index-v1.json          音乐库索引
│       ├── covers/                封面及版本记录
│       └── lyrics/                歌词缓存
└── cache/                         临时文件
```

安卓 SharedPreferences 继续作为设置的权威来源，`config/settings.json` 自动同步，直接编辑此快照不会修改应用设置。目录授权仍由安卓系统管理。可重建内容与配置分开，重建缓存只清理 library 和临时数据。外部存储不可用时自动使用内部 storage 目录，设置页显示实际位置。

同包名、同签名覆盖安装／升级继承已有数据，首次升级自动从旧内部 `files/library-cache` 迁移，文件复制完成后才删除原副本，失败保留原文件供重试。卸载由系统清空本应用内外部专属数据；系统备份与设备迁移恢复已禁用，重新安装不主动恢复旧目录和缓存。不会向音乐来源目录写入缓存，也不会删除用户音乐和 LRC 原文件。


“查看本地缓存”现在打开带独立导航栏的全屏管理页面，列出当前音乐库缓存、旧版内部缓存残留、内部及外部临时文件。列表显示相对文件名、文件类型／封面缩略图、大小和修改时间，点按查看完整路径并可删除单个文件；长按进入多选，支持全选、取消全选、批量删除和清理全部缓存。扫描期间禁止删除，文件遍历、缩略图解码和删除在后台执行。删除不会立刻触发重扫；后续按需使用时可重新生成派生缓存。config、收藏、歌单、音乐与原始 LRC 不参与清理。

旧版本音乐库缓存位于 `/data/user/0/com.xcosmos.minivoice/files/library-cache/`（`/data/data/com.xcosmos.minivoice/files/library-cache/` 通常指向同一应用数据位置），更早的临时封面在 `/data/user/0/com.xcosmos.minivoice/cache/covers/`。覆盖升级后可在缓存管理页清理残留，不需要先卸载。


未添加音乐目录时保持空库，不请求整机音频读取权限，也不再默认读取 MediaStore。已有系统音乐库来源的旧索引不会恢复为当前文件夹库；必须手动添加目录才扫描。安卓应用设置中的“清除缓存”仅清除系统临时缓存，不等于“清除存储／数据”，不会重置目录授权、配置或持久索引；应用内缓存页可单独清理派生文件。

设置页和缓存页使用非浮动的全屏页面主题，状态栏以页面背景覆盖且图标跟随深浅主题；系统导航区透明，滚动内容延伸到手势条下方，控件单独避让底部安全区。缓存页采用轻量圆角操作按钮，底部清理按钮悬浮，多选框使用清晰的圆角描边、绿色填充及白色勾选，并提供辅助功能选中状态。


音乐墙竖屏播放条在约 3 秒无触屏操作后缩为左下角 56 dp 圆形玻璃按钮，与其他三个圆形工具保持尺寸和边距一致；右下角页面设置同步下降，形成四角布局。点击圆形按钮以与搜索相近的先轻微放大、再水平展开的动画恢复播放条，收回使用连续形变和淡出。操作进度条、长按、键盘输入、侧栏、其他窗口、展开播放器时不会触发收起。播放中，卡片状态徽标与圆形播放按钮共用连续变化的音柱；暂停后保持静态播放图标。播放条保留白色圆形滑块及细轨道。


音乐墙绘制与玻璃背景采样分开：屏幕以全分辨率 RenderNode 绘制场景，玻璃仅引用该场景的显示列表，不再重复调用墙面的绘制和命中区域生成。双击可播放／暂停已聚焦卡片，单击聚焦中的同一卡片不重启动画；真实拖动才冻结当前相机和回流形状，按下手指不再取消聚焦。待布局定位保留是否需要动画的语义。

高清封面与普通墙图使用分离缓存，聚焦图保留引用；请求按 URI、来源版本、尺寸区分，并为聚焦请求提供独立加载通道。旧的小尺寸缓存会尝试一次重新读取更清晰的内嵌或同目录图片；原始图片确实很小时不会在每次启动重复重读。文件迁移、缓存删除及损坏后会重新解析有效路径／来源。缩放百分比按分类页保存，聚焦卡片也按相同比例缩放，不再因重新布局把卡片尺寸强制固定成另一比例；异常手势采样不会写入无效缩放值。


播放条的无操作收起时长统一为 3 秒，横屏也适用；无论横竖屏，展开播放器时均隐藏独立播放条。侧栏、播放队列与音乐墙配置面板增加深色底的遮盖强度，减少底图对文字的干扰。

卡片布局按实际屏幕尺寸计算字号、按钮触控区域和间距，覆盖 60%–120% 缩放；低比例精简模式仍可显示当前歌词片段，长歌词按空间限制换行并保留省略提示，不侵占操作区。展开封面恢复全屏铺满，不使用补背景或左右分栏；通过本地人脸检测选择裁切位置，优先保留完整的脸部范围。


资源开销修正：玻璃背景仅采样按钮覆盖的小区域，取消静止时自行请求每帧重绘；播放状态音柱和歌词采用最高约 20 fps 的持续更新，只在窗口有焦点且显示当前播放卡片时刷新。页面失焦／进入后台停止音乐墙动画时钟和进度轮询；歌词排版和可见瓦片查询结果缓存复用，隐藏旧页面不继续写入文本布局。

封面按实际卡片尺寸请求 256/512/640/1600 级别，当前可见图片由 viewport working set 保留引用，独立于共享 LRU。低清异步结果不能覆盖已加载的高清图片；升级高清期间显示已加载图片。普通请求最多四个，移出视野的排队任务取消；任务使用独立编号，旧回调不能清掉新请求。解码异常或内存失败也会释放请求状态，并延迟重试，防止永久等待或快速重试。

展开裁切使用系统本地 FaceDetector 在后台分析 RGB565 缩小副本，缓存归一化的人脸范围至 covers/*.faces，不访问网络或相机。构图评分优先保留完整人脸及额头、下巴边距，多人封面尽可能保留多张脸；极端长宽比无法保留所有脸时选择保留得分更高的位置，检测不到时采用保守偏上的居中裁切。迟到的人脸结果平滑调整裁切，不突然跳变；检测任务有并发上限，结果与几何计算均缓存，避免每帧识别。
