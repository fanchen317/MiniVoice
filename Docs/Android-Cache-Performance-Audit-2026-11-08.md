# Android 缓存、音乐墙与平台功能梳理（2026-11-08）

## 范围和平台原则

当前 Android 正式入口为 PortablePlayerActivity → Android WebView → Shared/UI/PortablePlayer；PlaybackService 管音频与媒体通知，LibraryScanService 管后台扫描，SAF 管用户授权目录。旧 HomeScreen/原生音乐墙不是本轮扩展或回退入口。

按本次用户补充，Android 沿用 Android 的触控、系统返回、安全区域、目录授权、后台扫描通知与系统媒体服务。左下角音乐墙播放条、高密度歌词画布及其光效保留。iOS 居中播放条、WKWebView 截图动画、Home 手势处理不移植到 Android。对齐的是适用业务能力、缓存正确性与性能机制，不要求两平台布局相同。目前不存在独立“高性能模式”开关；本轮直接优化现有高负荷路径，不通过关闭材质、歌词或高清图降低功能。

## 已落实的瓶颈处理

| 链路 | 原有问题 | 本轮实现 |
| --- | --- | --- |
| 图片请求 | 每个图片请求遍历全库，512px 位图重复 JPEG 编码；聚焦直接读取原图 | 授权歌曲 ID 索引；版本化 wall320/card960/detail2048/original 独立资源；原图显式保留，聚焦采用2048档 |
| 编码资源 | 同图重复工作，滑出再返回可再次解码/编码 | 8MiB 编码字节 LRU，同 key 在途合并；原图不驻留编码内存；失败可重试 |
| 解码调度 | 多张墙图与高清请求争抢资源 | 原生最多2路图片提取/编码，墙图最多1路，留出高清容量；限幅实际输出尺寸，避免底层1600备用图绕过320档 |
| 磁盘派生 | 缺少 WebView 可复用编码文件与统一预算 | 独立 web-artwork 256MiB / 30天 LRU，超限回收到7/8；原子写入，访问时间每文件最多一分钟落盘一次 |
| 清理与压力 | 清理不能可靠触发前端重建，旧工作可能回填 | 清理代次、图片 URL epoch、catalog revision 联动；内存压力释放编码及原生 LRU；flight 固定创建代次，清理后的加入者不能复活旧缓存；单个等待者取消不破坏共享工作 |
| 播放轮询 | 每450ms主线程排序最近播放、重建歌单/队列、重复传送歌词 | snapshotRevision 缓存冷字段；偏好/队列/歌曲/曲库变化失效；进度、播放、扫描和导航仍及时传送；共享入口保留数组身份，memo 不再每次序列化歌单 |
| 连续平移 | 预解码仅覆盖切歌，画面移动时才发现下一窗口 | 按最新方向预测最多420 CSS px，预热未来窗口，最多48项/24MiB decoded保留集；不增加海报DOM，不等待预热才移动相机；方向变化丢弃旧排队工作 |
| 焦点与预取 | 邻图排队可延迟新焦点 | 焦点请求提高排队优先级，同 URL 共享；保留解码就绪后交接、跨歌身份隔离及展开/收起几何 |
| 动画 | 惯性启动后开启减弱动态仍继续移动 | 惯性逐帧检查减弱动态并停止在当前位置；聚焦动画也按运行时偏好直接完成到真实布局 |
| 大字歌词 | 每字每帧重扫字符时间轴并 measureText | 每帧一次游标/包络计算、布局缓存字宽、歌词二分定位；保留原像素密度/反光/时序/绘制效果 |
| iOS 小修 | 内存警告后的读者加入旧flight可回填旧结果 | ArtworkRequestCache 将内存代次绑定flight创建，仍返回有用字节但不重新驻留旧结果 |

320/960/2048为最长边上限，小原图与底层采样可产生更小图像，不承诺每张图片都达到此像素数。所有预算均为工程配置，不是实测进程峰值。24MiB decoded保留集不包括WebView、可见DOM/GPU纹理及最多3个活动预解码；8MiB不包括解码位图；256MiB仅限制新增web-artwork目录。

既有 covers 是扫描时准备的1600px主缓存，按授权曲库清理，没有固定磁盘字节上限；原生位图LRU上限分别24+20MiB，逐歌预览按曲数缩小、以约24MiB为工程预算。该部分后续应在大量文件、慢SAF提供方及磁盘紧张下进一步评估，不能声称本轮已经限制Android全部缓存或消除首次扫描成本。派生资源读取/写入失败不阻止可用图片返回，不修改用户音乐、歌词、版本、签名与正式数据路径。

## 功能对齐结论

| 范围 | 结论 |
| --- | --- |
| 收藏、最近、歌单、队列、五种播放模式 | 共享业务入口已接入；本轮补齐Android冷快照增量与变更失效 |
| 目录、递归扫描、扫描进度/失败 | Android保留SAF与后台服务通知；不复制iOS目录/前后台执行策略 |
| 缓存统计、选择清理、曲库检查、歌手归并、歌词查看 | 两端已有宿主接入；Android统计新增显示封面目录，清理同步失效页面资源 |
| 歌曲/歌词/插图编辑 | 按产品标准，Android手机保留信息和歌词查看，不新增编辑入口 |
| 布局、手势、媒体入口 | 平台特色保留；共享状态/取消/错误语义对齐，功能存在不代表全部设备验收通过 |

Shared/UI/PARITY.md 中部分旧体验入口及“iOS未接宿主”的历史描述已过时；本轮状态以本文件和 ACCEPTANCE_STATUS.md 为准。

## 验证与剩余工作

合成逻辑覆盖编码LRU/同图并发/清理与内存警告竞态/取消等待者/失败重试/磁盘重启/路径隔离，冷快照100次轮询复用与真实变更失效，预测窗口/优先队列/快速重试/数组身份。1037首Chromium Android/iOS夹具验证离屏预取、不增大全库DOM、不提升巨型平面、相机不中断、惯性中开启减弱动态及深浅主题。大字歌词新旧18组布局、126帧绘图指令等价检查保持一致（开发期对照，未声称真机视觉完全一致）。

标准门禁、共享/桌面逻辑、组件/音乐墙页面、Android构建与专用模拟器、iOS合成测试的最终结果及证据见 ACCEPTANCE_STATUS.md。初次音乐墙测试只释放最后一个被拦截decode，加入预热后无法释放焦点图片；现收集并释放所有拦截任务，保留原解码前不可覆盖、原海报节点必须保留、最终高清可见等断言，不放宽产品行为。

仍需 Android 手机/平板三样式×深浅×横竖真实触控/GPU验收、快速反向平移/连续缩放/随机切歌与立即收回、慢SAF/扫描并发、后台返回/系统内存回收与热状态分析。新目录初次冷读取、原图提取和不可用文件仍可能需要加载；不将提前预取解释为任何速度下绝不会加载。iOS WKWebView/真机、实体玻璃材质、偶发形变白线及Instruments/Perfetto性能测量独立待验收，不编造FPS或百分比。

本轮真实WebView回归还发现并修复SongList旧定位token在页面重挂载时重放，导致从歌手返回音乐库跳回顶部。定位消费记录移到PortablePlayer，普通返回不重放、显式新token仍可消费，并提高滚动revision阻止迟到恢复覆盖新定位。新增双宿主DOM回归检查返回413px及再次定位当前歌曲；专用模拟器完整结果见台账。


最终专用Android缓存模式返回UI_CACHE_PERFORMANCE_PASS；最终完整portable及独立wall均在译文按钮弹跳峰值>1.1的原断言处未通过（实采约1.085–1.086），未放宽阈值。完整portable已到墙面末段，但后续旋转关闭/快速切卡等不能由较早轮次或Chromium替代；旋转返回后的固定时间关闭断言也保留为待验收。APK为本轮定向验证构建，完整结果、设备环境及日志见台账。不得将此交付称为全部Android动画已验收。
