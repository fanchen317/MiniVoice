# MiniVoice 体验版产品与验收标准 v1

本标准是 Android 与 Mac 体验版后续开发、修复和交付的首要项目约束。现有实现不等于全部达标；不得把有代码、能编译或接口已接通写成通过验收。

## 1. 范围与产品身份

- 当前只完善 Android（手机、平板）和 Mac（电脑）。暂停新增 iOS、Windows、鸿蒙、Linux 宿主、页面和功能分支。
- 手机和平板以 Android 为触控基准；电脑以 Mac 为键鼠基准。窄 Mac 窗口仍是桌面，宽平板仍是移动端。
- 对外统称“体验版”。已有 Mac-debug 名称、标识与配置隔离继续保留；未明确要求时不改包标识、不迁移或覆盖正式版数据。
- 为未来平台保留清晰适配接口，但不为了尚未实施的平台增加抽象、占位入口或宣称已支持。

## 2. 自有组件与平台边界

- 应用内容按钮必须经 ActionButton；图标用应用 SVG 路径。选择、勾选、数值步进、滑块、滚动条、菜单和弹窗必须用共享组件，不散落浏览器原生外观控件。
- 可以使用 input/textarea/button 等语义基础实现 IME、键盘和辅助功能；这是基础语义，不是直接采用系统内容控件。按钮基础元素只允许在 ActionButton 内创建。
- 磁盘、授权选择器、音频、系统媒体控制、窗口及操作系统菜单由平台适配层承担。页面不自行拼接任意文件路径或调用平台私有 UI。
- 共用组件语义、状态规则、协议与可复用逻辑；手机/电脑的布局和输入策略分开。三种样式使用同一业务行为，并允许明确命名的视觉皮肤，禁止通过偶然 CSS 级联维持差异。
- 新的或修改过的页面不得跳回旧原生内容面板补功能。未支持的能力应说明并禁用，不能以虚假成功代替。

歌曲编辑范围：Mac 体验版提供歌曲信息、歌词和插图编辑；Android 手机端暂不提供编辑入口，保留信息与歌词查看。已有底层写入/恢复代码保留，不以此作为继续扩展移动编辑页面的理由。

深浅模式入口统一在设置页；手机和电脑的侧边栏不提供独立主题切换。Android 音乐墙播放条固定左下角，展开仍从该位置变形，设置按钮保留右侧。

## 3. 三种样式与视觉

| 样式 | 材质与布局约束 | 不得破坏 |
| --- | --- | --- |
| 音乐库 | 层级清晰的目录/列表、歌词区、播放栏；高斯模糊材质 | 歌曲信息稳定、固定区不轻微滚动、歌词高度与展开 |
| 简易 | 简洁播放信息、歌词、目录切换；高斯模糊材质 | 触控目标、选中条圆角、侧栏与目录状态 |
| 音乐墙 | 全可用区域封面画布、液态玻璃工具/侧栏、独立聚焦卡片与播放条 | 拖动/缩放连续、可见封面不被错裁、焦点/歌词/封面不拉伸闪屏 |

- 每种样式必须同时验收浅色和深色，跟随系统模式必须生效。背景、描边、文字、图标、禁用和选中状态一起适配。
- 玻璃材质必须有实际采样/背景内容、模糊和透明层次；不能把纯色盖板称为高斯模糊。正文可读性优先，必要时用稳定遮罩提高对比。
- 正文对比目标至少 4.5:1，大字和必要控件轮廓至少 3:1；动态封面背景应以固定测试封面检查。不宣称未测量的对比度已通过。
- 图标不只检查外框：对称图形的实际绘制中心偏差不得超过 1 CSS px。播放三角形等视觉补偿必须由组件明确记录，不能遗留通用负 margin。
- 普通触控目标至少 44×44 CSS px；Mac 常用图标目标至少 28×28。音乐墙画布与缩放歌词行的几何例外必须在组件中声明，由父画布承担手势，不以通用最小尺寸挤坏布局。
- 横屏、窄窗口、安全区域和软键盘不得造成重叠、按钮出屏或不可点击。

## 4. 交互与动画

- 同一含义的按钮，在同一设备家族内拥有一致的触发、选中、忙碌、禁用和取消规则。按钮图标必须来自应用图标库。
- 进度滑块拖动时显示用户预览，轮询不得抢回滑块；释放提交，取消恢复；键盘支持步进和端点。
- 滚动条闲置隐藏、滚动显示、可拖拽；不可与标题/展开按钮重叠，不额外显示不需要的轨道。
- 圆形/长条变形使用同一持续存在的材质容器，尺寸、内容和点击区域协调变化。动画结束必须与真实布局相同，不能用替换节点造成闪屏。
- 连续点按、快速切卡片、动画中拖动、取消触摸、旋转和焦点丢失均须有确定结果；旧动画不能覆盖新手势。
- 尊重减弱动态效果。动画必须可打断，不能用强制等待阻断操作，也不能以动画改变业务数据。
- 手机系统返回顺序：最上层编辑确认/弹窗 → 搜索 → 选择模式/侧栏 → 展开/分组页面 → 应用退出；各组件不得同时消费一次返回。
- Mac 提供右键、键盘导航、Esc、焦点限制及关闭后焦点恢复；文本输入期间不得触发播放器全局快捷键。

## 5. 状态与数据

- 歌曲、分组和歌单用稳定身份。返回和重启按页面恢复排序、查询、滚动锚点与像素偏移、展开状态、音乐墙相机；临时弹窗和输入焦点不强制恢复。
- 隐藏列表、加载中列表、空结果不得覆盖有效滚动位置。目录/分组进入返回不能靠反复补偿滚动伪装恢复。
- 点击系统媒体入口直接定位当前歌曲，不做跨长列表的缓慢连续滚动。
- 扫描中显示加载/进度，不展示误导性的“暂无文件”。失败与真正空内容区分。
- 文件操作只能针对已授权、仍在音乐库内的对象；写入前校验，失败保留草稿。原文件写入必须有备份、校验和恢复，特殊格式明确拒绝。
- 重复候选不自动删除；应用内歌词与原文件写入明确区分；失败不得显示成功。

## 6. 验收矩阵与阻断规则

| 范围 | 必须验证 |
| --- | --- |
| Android | 三种样式 × 深/浅；手机横/竖、平板横/竖；系统安全区域、软键盘、返回与重启 |
| Mac | 三种样式 × 深/浅；窄/普通/宽窗口；鼠标、键盘、右键、焦点与窗口重开 |
| 每个受影响组件 | 默认/选中/按下/禁用/忙碌/错误（适用时）；连续操作与取消 |
| 音乐墙改动 | 聚焦/切换/收起/展开、缩放/拖动、动画中打断；大音乐库；封面与歌词的边界、可见区 |
| 数据改动 | 授权校验、保存回读、返回/重启恢复；破坏性写入的失败与恢复 |

- 阻断：崩溃、数据损坏/丢失、整页空白、主要操作不能触发、状态恢复失败、浅/深模式不可读。未关闭时不能称“稳定版”或“全部完成”。
- 定向体验包可以交付，但必须列明已修复内容、实际运行的验证、未验证和未解决项；不能把定向包称为整体验收通过。
- 自动化只覆盖能自动验证的部分；模拟器不能替代真机 GPU/材质/触控验收，截图存在不能证明动画流畅。
- 不编造 FPS、完成百分比或跨平台支持。发现标准与存量实现不一致时，记录缺口并修复，不通过放宽标准隐藏问题。

## 7. 执行入口

构建前运行 `node Scripts/check-ui-standards.mjs`，违规立即失败。它负责内容控件与原生回退入口的静态边界，不代替视觉和运行验收。

按修改范围运行：

- 共享逻辑：`node --test Shared/UI/test/*.test.mjs`
- 桌面逻辑：`npm --prefix MacOS/Desktop test`
- 自有组件交互：`bash Scripts/test-desktop-components.sh`
- 实际页面/音乐墙：`bash Scripts/test-wall-version.sh`
- Android：构建测试 APK，并在专用模拟器执行 portable；数据写入改动另执行 tags。测试不得覆盖用户手机或真实音乐库。
- 音频标签：`bash Scripts/test-audio-tag-writes.sh`
- Mac：使用隔离测试偏好域验证打包后台；包签名校验。

只有文档修改不要求重跑全部界面测试。修改、失败或未解决风险出现后，再扩大验证范围；已通过且未受影响的检查不反复空跑。

当前验收台账见 `Docs/ACCEPTANCE_STATUS.md`；组件强制契约见 `Docs/COMPONENT_STANDARD.md`，实现说明见 `Shared/UI/COMPONENTS.md`。有冲突时以本标准和用户本次明确指令为准。
