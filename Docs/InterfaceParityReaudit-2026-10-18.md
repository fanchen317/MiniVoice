# SwiftUI + AppKit → Electron 复核清单（2026-10-18）

本文件记录修复前的复核结果。后续修复、单一发行入口和验收边界见 [实施记录](UnifiedApp-2026-10-18.md)。

结论：当前版本仍未达到 1:1。除系统材质差异外，还存在可复现的行为错误、入口遗漏和状态恢复差异。本文以当前源码为准，不沿用旧 README 中已经过时的“未迁移”结论。

## 复核范围与证据边界

- 对照 `Sources/MiniVoice/ContentView.swift`、音乐墙、歌词、滑块、歌单选择器及原生辅助窗口，与 `Desktop/src/`、Electron 主进程和 `DesktopEngine`。
- 对新版进行 Chromium 实际 DOM / 点击验证，使用 100 首模拟曲库，窗口 1280×820。没有操作用户音乐、收藏或真实歌单。
- 本轮未取得原版与新版同曲目、同时间、同尺寸的双端同步录屏，因此不提供“还原百分比”，也不将渲染实现不同直接当作可见差异。
- 本次仅审计；没有修改产品实现。上一轮音乐墙设置弹窗层级修复不再列为当前未修复项。

## 三、仍需双端视觉验收的部分

这些项目不能仅根据构建、单元测试或“算法参数已相同”认定 1:1，也不能仅因为使用 HTML 就认定视觉必定不同。

| 项目 | 本轮能够确认的范围 | 必须补的对照 |
| --- | --- | --- |
| 玻璃材质 | 原版系统材质 / AppKit 与新版 CSS + SVG displacement 实现不同；现有视觉近似不等于相同材质。 | 同封面、同明暗主题下，侧栏、圆形按钮、底部胶囊的静态 / 悬浮 / 按压截图。 |
| 排版与封面 | 存在缩字与图标的明确差异，但字号、基线、字距、阴影、连续圆角的剩余误差未逐像素量化。 | 长标题、中英文混排、双语长歌词、无封面、不同图片比例及 Retina 比例。 |
| 动画中间帧 | 部分几何和弹簧参数已有移植；封面飞行等仍缺失。CSS/WAAPI 过渡不能仅凭终态确认。 | 相同手势录屏对比侧栏、分类返回、专辑展开、碎片切换、搜索展开中断与连续 resize。 |
| 性能与跨窗口 | 主窗口 DOM 虚拟化、原生后台与辅助窗口已经存在。没有本轮原版/新版同场景的帧时间、焦点和多显示器记录。 | 大曲库 60/120Hz 滚动、连续拉伸；设置/编辑器打开关闭、文件选择器、全屏、跨屏恢复。 |

## 四、已恢复或应保持的内容

- 设置与歌曲信息编辑器已经通过 `DesktopPanels` 复用原版 `AppSettings` / `MetadataEditor`，包括原有在线封面、歌词编辑和高级工具；不能再笼统列作“未迁移”。本轮未对真实文件执行保存验收。
- 原音频引擎、桌面歌词、菜单栏控制、全局快捷键和窗口切换已有复用/桥接，不作为整个功能缺失报告。
- 音乐墙设置弹窗本轮前一项已移出墙面 containment，304×600 与较大窗口覆盖层命中验证、滚动及关闭验证已通过。它的原生 popover 外观仍属于视觉对照范围。
- 已记录的用户要求优先：60%–120% 缩放、最近播放去掉扫描和排序、静态内容不可选择、仅文本输入参与 Tab、搜索先整体放大再展开。以上即使与旧版不同，也不应为了还原而撤回。
- 原版分类页定位按钮此前被特意调整过；恢复其旧入口前应核对原要求，本次不将“分类一级页隐藏定位按钮”计入遗漏。

## 建议修复顺序

1. A01–A04：先修定位目标、未知分组、空状态遮挡和独立排序状态，避免继续出现“看起来像还原、实际操作不一致”。
2. A06–A10：补齐已有后台能力对应的主窗口入口，再补主窗口任务协议。
3. A05、A11–A13、A19：统一状态清理、视口保留、侧栏和转场，以及模态交互。
4. A14–A18：逐控件对齐滑块、歌词、设备面板、图标和空状态。
5. 固定曲目/时间/尺寸做双端截图及录像，最后验收材质、排版和连续动画；不使用未经测量的“完成度百分比”。
